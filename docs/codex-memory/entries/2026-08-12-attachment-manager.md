# 附件管理中心

## 需求

桌面端原先只能在正文中插入或打开附件，缺少统一查看本地占用、上传状态、文件缺失和无引用资源的入口，也无法从附件反查引用笔记或安全释放空间。

## 实现

- 标题栏在“导入导出”旁新增“附件管理”入口，弹层展示本地占用、待上传、文件缺失和孤立附件统计。
- 清单支持图片、文档、其他类型切换，按已上传、待上传、文件缺失、孤立附件筛选，并可搜索附件名称、MIME 类型或引用笔记标题。
- 每个附件可用系统默认应用打开、在 Finder 中显示；有当前笔记引用时可展开引用列表并直接定位，回收站笔记也能正确定位。
- 待上传附件沿用既有全库双向同步流程执行“重试上传”，不会引入只同步单个附件的第二套同步协议。
- 引用检查同时扫描所有当前笔记（含回收站）和 `note_history` 历史版本，并识别本地资源地址、内部附件地址及已上传远程地址。
- 只有当前笔记与历史版本引用数都为零时才允许清理；主进程在实际删除前再次检查。数据库记录删除后将本地文件移入系统废纸篓，远程文件不删除；移入废纸篓失败时恢复数据库记录。
- 底栏提供“一键清理”：操作前重新扫描并展示孤立附件数量与本地占用，只提交用户确认时的附件 ID；主进程逐项复用单附件安全清理，某一项失败会保留该附件并继续处理其他项，完成后展示成功与失败数量。
- 附件弹层限制在视口范围内，清单独立滚动；引用笔记列表在卡片内展开避免被滚动容器裁切，确认框层级高于附件弹层，并适配亮色、夜间和窄窗口。
- 单附件清理确认框使用固定标题，将文件名放入正文；确认框限制在视口内并对无分隔长文本强制换行，避免随机附件名撑出弹层。
- 第二版增加来源分层：本地资源、本站及子域资源、带服务端资源 ID 的上传结果归为“笔记附件”，其他远程资源标记为“外链缓存”并显示来源域名；可按来源筛选或搜索域名，底栏分别统计两类数量。
- 卡片中的大小/类型、来源、上传状态和引用数量统一为同一行的轻量标签，窄窗口空间不足时整组自然换行，减少重复文本行造成的视觉噪声。
- 引用笔记列表使用紧凑字号；桌面宽度下文件操作固定在卡片最右侧，不再独占一行，窄窗口才回落到引用区域下方。

## 边界

- 本版本不做附件哈希去重、批量目录迁移或云端文件删除。
- 任意 HTTP(S) 站点的图片与附件仍会下载缓存，来源分层只改变管理界面的说明与筛选，不限制缓存范围，避免原始外链失效后无法访问。
- “文件缺失”表示本地文件不可用，即使资源已有远程地址也优先提示缺失。
- 清理操作属于显式用户操作；开发与验证过程不执行真实附件清理。

## 验证

- 数据库回归覆盖当前笔记引用、仅历史引用、孤立判定及引用附件拒绝删除。
- UI 回归覆盖 IPC 暴露、统计与操作入口、确认框层级和引用列表防裁切样式。
- 来源分类回归覆盖本站、子域、服务端签发资源、第三方域名及相似域名，UI 回归同时锁定来源筛选、徽标、统计和任意站点下载行为。
- 批量清理单元测试覆盖全部成功、单项失败继续执行及空候选不触发删除。
- Playwright 验证筛选、引用标题搜索、确认框层级，以及 1280×800 亮色/夜间和 600×700 窄窗口布局。
- 发布前运行完整测试、类型检查、生产构建，并核对 macOS ARM64 免安装应用内容。
