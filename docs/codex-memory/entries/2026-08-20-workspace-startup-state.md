# 2026-08-20：工作区启动状态边界

## 问题

启动时即使没有本地标签会话也会兜底打开第一篇笔记；工作区首次装载还会将所有文件夹标记为展开。

## 修复

- 空标签会话不再使用第一篇可用笔记作为兜底，编辑区保持空白。
- `applyWorkspace` 只覆盖工作区数据，不再隐式修改文件夹展开状态。
- 恢复有效活动标签时，通过文件夹父链只展开活动笔记所在目录及其祖先路径。
- 关闭最后标签时先保存空标签会话，再处理正文草稿，避免慢保存或 macOS 关窗销毁渲染器后仍恢复旧笔记。
- “未分类”初始保持折叠；主动打开其中笔记时仍可按现有选择逻辑展开。
- macOS 红色关闭主窗口也执行保存握手，成功后仅销毁窗口；避免组件卸载取消待写入的空会话。
- 工作区同步通知刷新列表时区分“没有活动标签”和“原活动笔记失效”：前者保持空白，后者才选择替代笔记。
- 活动笔记同步后标记为已删除时按失效处理，只选择未删除的替代笔记；没有替代项则清空编辑器。
- 本地标签会话的持久化结构、同步和普通笔记选择逻辑保持不变。

## 验证

- Electron E2E 在同一临时数据目录内覆盖空会话启动及保存会话后的重启恢复。
- Electron E2E 覆盖关闭最后标签后立即关窗、重新激活同一应用进程的竞态。
- Electron E2E 覆盖空标签状态收到工作区变更通知后仍保持空白。
- Electron E2E 覆盖同步删除活动笔记后切换到下一篇可用笔记。
- 静态回归测试锁定无首篇兜底、无全量目录展开和祖先路径计算入口。
