# 工作区正文按需加载与 SQLite 全文搜索

## 需求

启动工作区不再把所有笔记完整正文传到渲染进程；列表只需要标题、元数据和摘要，同时保留标题、正文、标签及文件夹搜索能力。

## 实现

- 桌面端 SQLite 使用本地专用 `note_previews` 表保存正文前缀；首次升级只回填一次，之后由触发器随新增、编辑、同步导入和删除增量维护，不加入同步协议。
- `listWorkspace()` 显式查询笔记元数据并关联本地摘要缓存，不再执行 `SELECT * FROM notes` 或读取完整正文；返回最长 240 字摘要，并以 `contentLoaded: false` 标识不可编辑内容。
- 编辑器打开笔记前通过 `note:detail` 读取完整正文；详情回写工作区后才允许进入草稿和自动保存流程，避免摘要覆盖正文。
- SQLite 使用 trigram FTS5 索引标题和完整正文，由 notes 表触发器实时维护；短关键词回退到数据库子串查询。
- 快速打开可额外匹配标签和文件夹，侧边栏搜索仅匹配标题与完整正文。
- 同步结果、完整备份和 Markdown 导出使用独立完整工作区快照，只查询一次完整正文，不受列表摘要化影响。
- 历史详情使用独立已加载标记，合法空正文不能被误判为尚未加载；同步冲突处理在展示和启用覆盖操作前读取两侧完整正文。
- FTS 首次迁移只执行一次，之后由触发器增量更新。

## 验证

数据库测试覆盖本地摘要缓存迁移和触发器、摘要与详情隔离、摘要之外正文命中、标签/文件夹匹配和编辑后索引更新；边界测试约束列表 SQL 不得重新读取完整正文，前端静态测试确保编辑前读取详情且不再扫描全部内存正文。
