# 快速打开高级搜索

## 需求

桌面端全库快速打开需要在正文全文检索之外组合结构化条件，同时继续由本地 SQLite 查询，避免读取所有完整正文到渲染进程。

## 实现

- `searchNotes` 支持 `folderIds`、`tagIds`、`updatedAfter` 和 `pinnedOnly`，条件可以同时生效。
- 文件夹筛选在界面层展开为所选文件夹及全部子目录，再交给数据库筛选。
- 快速打开弹窗增加可收起的筛选栏，提供文件夹、标签、最近 7/30 天或一年、仅置顶和一键清除。
- 筛选控件不使用系统原生下拉；文件夹复用 `FolderPickerPopover` 的可搜索树形弹层，标签和时间使用同视觉体系的自定义弹层。
- 筛选值使用 13px 辅助字号和 32px 控件高度，避免与主搜索输入及结果标题争夺视觉层级。
- 文件夹、标签和更新时间弹层选项统一为 11px；更新时间菜单必须显式设置字号，避免继承系统按钮默认的 16px。
- 已选文件夹、标签和更新时间显示独立 X，可只清除当前条件且不会打开筛选弹层；右侧“清除”仍用于一次清空全部条件。
- 最近搜索词支持独立 X 删除和一键清空，变更立即写入本地存储，不影响当前关键词、筛选条件或云端数据。
- 有筛选条件时允许关键词为空，直接按更新时间和置顶顺序返回本地结果。
- 文件夹、标签、时间和置顶条件必须在 SQLite 的 `LIMIT` 之前应用，不能先截取 1000 条候选再在内存筛选。
- 搜索继续只返回短摘要，完整正文仍在打开笔记时按需读取。

## 验证

- 数据库测试覆盖多条件组合和空关键词筛选。
- 数据库测试使用超过 1000 篇的候选集验证结构化筛选不会漏掉较早笔记。
- Electron E2E 明确断言筛选区不存在原生 `select`，并覆盖复用文件夹弹层、标签弹层和置顶组合。
