# 笔记批量管理

## 需求

桌面端需要对当前筛选结果进行多选，并一次完成移动文件夹、增加或移除标签、置顶或取消置顶、移入回收站和导出所选笔记。

## 实现约束

- 批量模式直接复用现有文件夹树，在未分类和各层级笔记节点前显示复选框；不得切换为平铺列表，以保留目录上下文和展开状态。
- 批量栏只展示选中数量、全选和完成；移动、增删标签、置顶、导出及回收站操作集中到任一选中笔记的右键菜单，避免侧栏常驻大量按钮。
- 批量移动与详情属性区移动必须共同使用 `FolderPickerPopover.vue`；搜索、层级缩进、未分类、选中态和空结果只维护一份，并按各自触发位置定位。
- 文件夹选项只渲染原始 `name`，层级完全由 `depth` 缩进表达；不要同时使用带树形前缀的 `label`，否则会出现重复的 `└` 符号。
- 共享组件的输入框规则不得限定在 `.properties-row` 下；搜索框边框、焦点、尺寸和外观必须由全局 `.folder-picker-search input` 规则统一，否则批量弹层会退回原生输入样式。
- 普通笔记右键菜单提供“选择”，可直接进入多选并选中当前项；多选时保留复选框和文档图标两列，复选框顶部与文档图标对齐，不得替换或隐藏文档图标。
- 回收站笔记同样可通过标题栏入口或右键“选择”进入多选，选中项右键提供“恢复所选”和二次确认的“永久删除”；多选模式允许随文件夹删除的笔记打开批量菜单，这类笔记单独恢复时自动进入未分类，避免恢复后不可见。
- “全选”只作用于当前筛选和搜索结果。
- 数据修改通过 `bulkUpdateNotes` 在单个 SQLite 事务内完成；任一笔记或目标文件夹无效时整体回滚，避免部分成功。
- 移入回收站必须二次确认；所选导出只包含未删除的选中笔记及其引用附件。
- 前端成功后更新本地工作区并标记待同步，仍由下一次全库同步统一上传。
