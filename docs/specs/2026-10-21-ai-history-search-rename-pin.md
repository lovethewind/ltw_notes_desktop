# AI 助手：历史对话的搜索 / 重命名 / 置顶

- 日期：2026-10-21
- 前置：`2026-10-21-ai-conversation-history.md`（历史落库 + 覆盖层列表）
- 范围：仅桌面端；`ai_conversations` 加一列，**不参与同步**、不改网页端

## 背景

上一版历史列表只能「看」和「删」：

| 现象 | 原因 |
|---|---|
| 对话一多就得一个个往下翻 | 列表只有时间序，没有搜索 |
| 标题都是「第一句问题的前 30 字」 | 自动标题，改不了 |
| 常问的那条被新对话挤到下面 | 只有时间序，钉不住 |

原 spec 明确写过「不做会话搜索 / 重命名 / 置顶 —— 那是下一档（B）」，这篇就是那一档。

## 设计

### 搜索：走后端，不只搜标题

标题只截了**第一个问题**的前 30 字，追问里的关键词（例如第二轮才提到的「线程池」）
在列表里根本不存在。所以匹配范围是「标题 + 任意一轮的提问」：

```sql
WHERE conversation.title LIKE ? ESCAPE '\'
   OR EXISTS (SELECT 1 FROM ai_conversation_turns hit
              WHERE hit.conversation_id = conversation.id
                AND hit.question LIKE ? ESCAPE '\')
```

- `%` `_` `\` 先转义，否则用户输入「100%」会变成通配符匹配到全表；
- 只匹配**提问**，不匹配回答：回答动辄上千字，命中面太大，且用户记的是自己问了什么；
- 空关键词等于不过滤（界面清空搜索时就是这条路径）。

界面不传关键词时行为与之前完全一致，`listAiConversations()` 可无参调用。

### 重命名：行内输入，不弹窗

历史列表本来就是一列标题，弹个对话框改名太重。点铅笔 → 该项变成输入框
（`height: 30px`，与列表项同区），`Enter` 提交、`Esc` 取消、失焦提交。

- 标题压平空白、截到 80 字；空标题视为取消（`return false`）；
- **不改 `updated_at`**：改名是整理动作，不该把一条旧对话顶到列表最前，
  否则刚整理好的顺序会被一次改名打乱，看着像排序坏了。

### 置顶：加一列，排序与保留策略一起改

```sql
ALTER TABLE ai_conversations ADD COLUMN pinned INTEGER NOT NULL DEFAULT 0
```

老库里这张表已经建好，`CREATE TABLE IF NOT EXISTS` 不会补列，所以走
`migrateLegacyColumns()` 的 `PRAGMA table_info` + `ALTER TABLE` 老套路。
新建库则在建表语句里直接带上该列。

排序：

```sql
ORDER BY conversation.pinned DESC, conversation.updated_at DESC, conversation.rowid DESC
```

保留策略也要承认置顶，否则「钉住」是假的：

- 30 天清理 → `DELETE ... WHERE updated_at < ? AND pinned = 0`；
- 50 条上限 → 先扣掉置顶占的名额，剩下的才轮到普通会话按新旧裁：
  `LIMIT MAX(0, 50 - pinnedCount)`，且只对 `pinned = 0` 生效。

置顶数量由用户手动操作产生，不设额外上限（钉满 50 条时不剩普通名额，属预期）。
与重命名同理，置顶**不刷 `updated_at`**。

### 界面

- 覆盖层顶部加搜索框（放大镜 + 自己的清除按钮，隐藏 macOS 原生小叉）；
  输入走 **220ms 防抖**，挂在 `@input` 上而不是 `watch` ——
  打开历史时会程序化清空搜索词，`watch` 会连带多查一次，列表白闪「读取中…」。
- 列表项右侧三个动作：置顶 / 重命名 / 删除，只在悬停或键盘聚焦（`:focus-within`）时浮出；
  标题 `padding-right` 从 32px 让到 78px。
- 置顶项：标题前一个淡蓝图钉 + 整行淡蓝底，让人一眼看出「它为什么不按时间排」。
- `li` 固定 `min-height: 52px`：改名时输入框只有 30px，不固定会让列表整体跳 22px。
- 搜索态不显示「清空全部历史」：那个动作是全局的，搜索时显示容易误解成「清空搜索结果」。
- 搜索无结果给专属空态（「没有匹配的对话，换个词试试」），不是一片空白。

## 验收

1. 输入关键词，标题命中与「某轮追问命中」两种都能搜到；`%` `_` 按字面匹配。
2. 搜不到时显示空态；点清除按钮回到完整列表。
3. 重命名后列表与打开后的对话标题都变了；空标题、`Esc` 不改动。
4. 改名后该项**不跳**到列表最前。
5. 置顶后排到最前（即使最旧），取消置顶回到时间序。
6. 置顶会话不会被 30 天清理，也不占普通会话的 50 条名额。
7. 搜索 / 改名 / 置顶后重启应用，结果仍在（都是库里的状态）。

## 不改动

- 不做「搜索回答正文」：命中面太大，且用户记的是自己问了什么。
- 不做多选、批量置顶、拖拽排序：50 条上限下收益很低。
- 不做历史列表的侧栏常驻版：面板只有 410px，覆盖层仍是当前最优解。
- 不参与同步：跨端契约里没有 AI 会话，网页端没有对应 UI。
