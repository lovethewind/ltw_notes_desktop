# 回答落地（插入正文 / 存为新笔记）

> 2026-10-21。前置：`2026-10-21-ai-assistant-conversation.md`（多轮 / 流式 / 停止 / 重新生成）、
> `2026-10-21-ai-conversation-history.md`（历史对话）、`2026-10-21-ai-selection-ask.md`（选区问 AI）。

## 问题

AI 回答区此前只有一个「复制」。想用它的内容只能手动复制、手动新建笔记、手动粘贴 ——
前面做的引用跳转、流式吐字、选区提问，价值都停在「看完就结束」。
用户实际要的是**问完就能接着用**。

## 目标

回答下方（气泡头部动作组）多两个动作：

| 动作 | 行为 |
|---|---|
| 插入到当前笔记 | 在编辑器**光标处**插入整段回答（含参考来源），不新建、不切换 |
| 存为新笔记 | 建一篇新笔记，标题取问题前 30 字，写完直接打开 |

**边界：只做「追加」，不做「改写」。** 不用回答替换选区、不润色现有正文 ——
那涉及选区映射、撤销粒度、误覆盖，风险量级完全不同（同 `ai-selection-ask.md` 的取舍）。

## 落地格式

`buildAiAnswerNoteMarkdown(answer, sources)` 是唯一出口，两条动作共用：

```markdown
线程池适合 IO 密集任务，阻塞操作必须拆到独立线程。[S1]

- **CPU 密集**：并行度不要超过核数
- **IO 密集**：可以显著超过核数，但要限流

---

**参考来源**

1. [并发方案](https://xinyue-note.local/<noteId>)
```

四条规则（都有单测钉住）：

1. **`[Sn]` 保留**。写进笔记后它仍是「这句有出处」的唯一线索；配合来源列表才找得回去。
2. **来源用有序列表，编号按原下标走**。主进程就是按数组顺序发 `S1`、`S2`，编号对齐才对得上；
   同一篇被命中两次时**跳过重复但继续递增**（不能让 `[S3]` 指到第 2 条）。
3. **分隔线而不是 `##` 标题**。来源不该进大纲跟正文抢层级。
4. **没有来源就不写这一段**。空壳小标题比没有更糟。

标题侧 `deriveAiAnswerNoteTitle(question)`：压平空白 → `Array.from` 按码点取前 30 字
（emoji 不会被切成半个代理对）→ 空问题退回「AI 回答」。与历史对话标题同一口径。

其余清洗：首尾空白、流式残留的 `[DONE]`、标题里 `[` `]` `\` 的链接转义。
正文为空（例如只吐了个终止标记）时返回空串，界面放弃落地并提示。

## 两个编辑器的插入实现

`markdownEditorRef` 现在要求 `insertMarkdown(markdown)`，两侧语义不同：

| | 富文本（笔记） | 源码（外部 `.md`） |
|---|---|---|
| 解析 | `markdownToSlice(text)(ctx)` → ProseMirror 节点 | 不做解析，按文本插入 |
| 落点 | 光标处；段落中间**先 `split`** 再插 | CodeMirror `changes: { from, insert }` |
| 自动排版 | 无（Markdown 本身就是排版） | **无 —— 不补换行、不折行、不动其他行** |
| 预览态 | 先 `togglePreview()` 回编辑态 | 先 `switchMode('source')` |

为什么要 `split`：第一次实拍发现插入内容黏在前半句后面
（「…再看机器规格。线程池适合 IO 密集任务…」读起来像原话的延续）。
插入的是独立内容块，就该独立成段；光标已在段首或空段落时不拆，避免平白多一个空段。

外部文件不补换行是保真红线：那是用户的磁盘文件，应用不能因为一次插入就重排其他行。

## 交互细节

- 动作按钮与复制、重新生成同一组，悬停气泡才浮出；`.ai-bubble-actions` 统一 `margin-left: auto`，
  单个按钮不再各自占位（否则第一个被推走、其余挤左边）。
- 「插入」在**没有打开任何笔记或文件**时置灰，并保持灰（悬停也不点亮），
  否则看着能点、点下去没反应。
- 判断目标是「编辑器在不在」而不是 `currentNoteId`：外部文件没有笔记 ID，但编辑器照样能接。
- 900ms 防连点，避免双击存出两篇一样的笔记。
- 结果用页面顶部那条既有 toast 反馈（`editorFeedback`，原 `linkCopyFeedback` 重命名而来）。

## 新笔记的归属

跟随**当前笔记所在的文件夹**：在「项目 A」里问出来的结论，默认落在项目 A。
`createNote(folderId)` 只接受文件夹，标题与正文必须再 `updateNote` 一次 —— 两步都要做。

## 已知限制

- 插入位置取编辑器最后一次光标位置。若用户点过 AI 输入框后直接按「插入」，
  落点仍是编辑器里上次停的地方（ProseMirror 保住了 selection）。
- 富文本序列化会把 `[S1]` 写成 `\[S1]`、`---` 写成 `***`（Markdown 等价写法）。
  这是编辑器往返的本性，不影响渲染与阅读。
