# AI 笔记助手 MVP

## 问题

用户需要借助 AI 在本地笔记中查找、归纳和分析信息，同时能够确认答案来自哪些笔记，并避免未授权上传附件或整库正文。

## 目标

- 在桌面端顶部提供始终可见的全局入口，用于开关右侧 AI 助手面板。
- 支持当前笔记、当前文件夹、全部笔记三个检索范围。
- 使用 SQLite FTS5 召回候选，只把有限数量的文本片段发送给 OpenAI 兼容接口。
- 回答附带结构化来源，点击来源可打开原笔记。
- API Key 使用 Electron `safeStorage` 加密后保存在本机配置文件，不进入 SQLite、同步或备份。
- 渲染层传给 Electron IPC 的设置必须是可结构化克隆的普通对象，保存成功后界面不得出现克隆错误。

## 非目标

- 不实现向量数据库、Embedding、图片识别、附件上传或联网搜索。
- 不让 AI 自动修改正文，也不保存对话历史。
- 不为具体 AI 厂商编写专用适配。

## 模块与接口

主进程新增 AI 助手模块，在 Electron IPC seam 后提供三个方法：

- `getSettings()`：返回地址、模型和是否已有密钥，不返回明文密钥。
- `saveSettings(input)`：校验并保存 OpenAI 兼容地址、模型和可选的新密钥。
- `ask(input)`：校验范围，召回候选，构造受限上下文，请求 `/chat/completions`，返回答案和来源。

渲染层通过一个独立面板模块消费该接口；`App.vue` 只负责开关面板和定位来源笔记。

## 行为约束

- 只接受 `http:` 或 `https:` 地址，API Key 不通过 IPC 回传。
- 单次最多发送 8 篇笔记，每篇正文最多 4000 字符，总上下文最多 24000 字符。
- 当前笔记范围直接使用当前笔记；其他范围从问题提取有限关键词并复用 FTS 搜索。
- 模型回答必须使用 `[S1]` 形式引用来源；渲染层按返回的结构化来源展示可点击卡片。
- 模型回答按 Markdown 渲染，并在进入 DOM 前净化不安全 HTML；提问按钮使用清晰可读的 `⌘ Enter` 键帽提示。
- 没有召回笔记、未配置模型或接口错误时返回可读错误，不产生本地数据修改。

## 验收标准

1. 可从应用顶部打开和关闭 AI 助手，并在三个范围间切换；无活动笔记时默认选择“全部笔记”。
2. 保存设置后再次打开仍可读取地址和模型，但读取不到 API Key 明文。
3. 提问会发送受限文本上下文，回答区展示引用来源，点击来源打开对应笔记。
4. 当前文件夹范围不会召回其他文件夹笔记；全部笔记范围排除回收站。
5. 附件 URL、Base64 内容和超过预算的正文不会进入模型请求。
6. 现有类型检查、单元测试和生产构建通过，并生成 macOS ARM64 免安装应用。
7. 回答中的加粗、列表等 Markdown 正常渲染，脚本不会进入 DOM，快捷键键帽尺寸清晰。

## 验证计划

- 纯模块测试：设置规范化、关键词提取、上下文清洗与预算、OpenAI 响应解析、错误语义。
- 静态集成测试：IPC、preload、类型和独立 Vue 面板接线。
- 回归：`npm test`、`npm run typecheck`、`npm run build`。
- 产物：`npm run desktop:build:mac:dir`，验证 `release/mac-arm64/心悦笔记.app`。
