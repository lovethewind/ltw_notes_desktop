# 工作区启动状态修复规格

## 问题

当前启动流程在没有本地标签会话时仍兜底打开第一篇笔记；工作区首次装载时还会将全部文件夹 ID 写入展开集合，导致文件夹树全部展开。

后续回归发现，关闭最后一个标签后立即关闭 macOS 窗口时，标签会话的防抖写入会随渲染器销毁而取消；再次激活仍在运行的应用会从 SQLite 恢复旧标签。“未分类”也仍以展开状态初始化。

## 预期行为

- 空标签会话启动后保持编辑区空白，不自动打开任意笔记。
- 文件夹树默认折叠，不因工作区数据刷新而自动展开全部目录。
- 存在有效本地会话时恢复活动笔记，并只展开该笔记所在文件夹及其祖先路径。
- 关闭最后一个标签时立即保存空会话，即使紧接着关闭窗口，再次打开也保持空白。
- “未分类”在没有主动选择其中笔记时默认折叠。
- macOS 红色关闭主窗口时先完成草稿与标签会话保存，再销毁窗口但不退出应用进程。
- 自动同步或其他工作区刷新发生时，空标签会话继续保持空白；仅当原活动笔记失效时才选择替代笔记。
- 同步将活动笔记移入回收站时，不继续加载已删除正文；切换到下一篇可用笔记，没有可用笔记则显示空白状态。
- 不修改 SQLite 会话结构、笔记数据、同步和普通选笔记行为。

## 验证

- Electron E2E 使用临时数据目录创建两级文件夹和笔记，验证空会话启动保持空白且根文件夹折叠。
- 同一场景保存活动标签会话后重启，验证恢复笔记并展开完整祖先路径。
- Electron E2E 先保存一篇活动笔记并产生待保存正文，再关闭最后标签并立即销毁窗口；重新激活应用后验证没有恢复旧标签，且“未分类”保持折叠。
- Electron E2E 向空标签会话发送同步使用的工作区变更通知，验证不会自动打开第一篇笔记。
- Electron E2E 模拟同步删除当前笔记，验证编辑器切换到下一篇未删除笔记。
- 运行工作区会话、标签页及完整回归测试。
