# AI 助手：历史对话（本机持久化 + 覆盖层列表）

- 日期：2026-10-21
- 前置：`2026-10-21-ai-assistant-conversation.md`（多轮 + 引用可点 + 流式）
- 范围：仅桌面端；新增两张表；**不参与同步**、不改网页端

## 背景

上一轮做完多轮和流式后，面板只剩「当前这一段对话」：

| 现象 | 原因 |
|---|---|
| 点 header 的「＋」就再也回不去了 | `resetConversation()` 直接 `turns.value = []`，无确认、无存档 |
| 关掉面板再打开对话还在 | 面板是常驻组件，`visible` 只控制显隐 —— 这点常被误解 |
| 退出应用全丢 | `turns` 只是 `ref([])`，没落盘 |

所以「有新对话、没有历史记录」的本质是：**「＋」是破坏性动作，而不是新建**。
上一版 spec 里写过「不持久化对话……需要接线到 SQLite 时另开 spec」，这篇就是那个 spec。

## 设计

### 存哪里

SQLite，跟笔记同一个档案库。不选 localStorage 的三个理由：

1. 会话里含笔记摘要片段，属于敏感数据，希望和笔记一起被「导出备份 / 清空数据」覆盖到；
2. 现有库是 `CREATE TABLE IF NOT EXISTS` 一次性建表、没有迁移框架，加表零风险；
3. `repository` 按档案（后端域名 + 账号）分库，会话天然跟随档案隔离，不会串号。

```sql
ai_conversations(id, title, created_at, updated_at)          -- rowid 兜底排序
ai_conversation_turns(id, conversation_id → cascade, position,
                      question, answer, sources_json,
                      citation_missing, created_at)
```

- `sources_json` 存 `{id, noteId, title, excerpt}`：不存的话恢复后 `[S1]` chip 点了跳不到、
  来源列表也是空的。摘要截断到 400 字、最多 12 条，防止整篇笔记进库。
- 只存 `status === 'done'` 的轮次。流式失败或中途关面板留下的半截回答不落库，
  否则恢复出来的对话里会夹一条永远写不完的回答。

### 保留策略

**最近 50 条 / 30 天**，在**新建会话时**裁一次（不是每追加一轮都扫全表）：

- 30 天按 `updated_at` 比，不是 `created_at` —— 一直追问的旧会话不该被清掉。
- 条数裁剪按 `updated_at DESC, rowid DESC`：`updated_at` 只到毫秒，同毫秒写入会打平，
  用 `rowid` 才符合「后动的在前」。

### 懒创建

点「＋」不落库，**第一轮答完才建会话**。否则连点几次就攒一堆没问过话的空会话。

- 首轮 `appendTurn` 传 `conversationId: null` → 主进程 `randomUUID()` 建会话并返回真实 ID；
- 渲染层回填 `conversationId`，后续轮次沿用；
- 传入不存在的 ID 时另起一条，不把轮次挂到空处。

会话标题取第一句问题的前 30 字，换行压成空格。

### 界面

`header`：历史 / 新对话（有轮次才出现，流式中禁用）/ 设置 / 关闭。

历史列表是**覆盖层**（`top: 64px` 铺到底，与设置覆盖层互斥），不是侧栏：

- 面板只有 410px，左边再切 220px 列表，正文区剩不到 200px；
- 复用设置覆盖层的定位与配色，不重排对话区，窄窗口不用改。

列表项 = 标题（单行省略）+ `相对时间 · N 轮`；删除按钮只在悬停时浮出。
底部「清空全部历史」**两段确认**（第一次点只把文案换成「再点一次确认清空」）——
历史删了进不了回收站，不恢复。

### 恢复语义

- 轮次还原成 `status: 'done'` 的气泡，`requestId` 留空（不参与流式匹配）；
- 正文走同一个 `renderAnswer()`，再 `TreeWalker` 补 `[S1]` chip；
- 恢复后可以继续追问：历史里带的是这整段（含恢复的轮次），最多 6 轮 / 6000 字；
- 删掉的正好是当前会话时，界面一起让位（清空气泡、`conversationId` 置空）；
- 「清空全部」只清库，**界面上的当前对话留着**，但脱离历史（再追问会另起一条）。

## 验收

1. 答完一轮后打开历史，列表出现一条，标题是第一句问题、副标带轮次数。
2. 点「＋」清空界面后，历史里那条**仍在**。
3. 点开历史条目，气泡、来源折叠、`[S1]` chip 全部回来，且能继续追问。
4. 关掉应用重新启动，历史仍在（跨重启）。
5. 删除单条后列表移除；删除的若是当前会话，对话区一起清空。
6. 「清空全部历史」需点两次；第一次点击后列表条数不变。
7. 超过 50 条时只保留最近 50 条；30 天前的会话在下次新建时被清掉。
8. 问题或回答为空不落库；流式失败的轮次不进历史。

## 不改动

- **不参与同步**：跨端契约里没有 AI 会话，网页端没有对应 UI；会话含笔记片段，留本机更可控。
  会话表不写 `outbox`、没有 `dirty` 字段。
- 不做会话搜索 / 重命名 / 置顶 / 侧栏常驻列表 —— 那是下一档（B），数据层已经够用，改的是布局。
- 不做多标签或多窗口并发写同一会话：按 `position = MAX+1` 追加，单窗口顺序写入。
- 不做「停止生成」：仍与上一版一致，关面板只是丢弃增量，主进程请求会跑完。
